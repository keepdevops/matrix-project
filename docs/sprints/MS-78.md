# MS-78: Mode Preset Import / Export

## Goal
The preset system (`/api/presets`) stores named mode configurations
server-side, but users have no way to:
- Export the current mode config as a downloadable JSON file
- Import a preset from a local JSON file without manually crafting a PUT request
- Duplicate an existing preset under a new name

This sprint adds import/export to the preset UI and a duplicate action.

## Background
`GET /api/presets` returns `{ name: { agents, synthesizer, max_select, ... } }`.
`PUT /api/presets/:name` saves a preset bundle.
`DELETE /api/presets/:name` removes one.
`POST /api/presets/:name/apply` applies a preset to the active mode.
The JS `BrewConfigPanel` (or equivalent) already lists presets and has apply/delete.

## Scope

### C++ — preset export endpoint

- **`cpp_core/src/coordinator_routes_presets_url.h`** — add
  `GET /api/presets/:name/export` that returns the single preset as a
  JSON file download (`Content-Disposition: attachment; filename="<name>.json"`).
  This lets `curl` or browser fetch download a named preset.

### JS — export button

- **`src/api/presetsApi.js`** (new) — `exportPreset(name)` triggers a browser
  download of `GET /api/presets/:name/export`; `importPreset(name, data)`
  calls `PUT /api/presets/:name`; `duplicatePreset(src, dst)` fetches src
  then saves as dst.

- **`src/components/PresetActions.js`** (new) — row-level action buttons for
  each preset: Apply (existing), Export ↓, Duplicate, Delete. Extracted from
  whatever currently renders preset rows to keep each file ≤ 110 LOC.

- **`src/components/PresetImport.js`** (new) — file input (`accept=".json"`)
  + name input. On submit: reads file as JSON, validates it has at least one
  known field (`agents`, `synthesizer`, `max_select`), then calls
  `importPreset(name, data)`. Shows success/error inline.

## Files NOT touched
- `coordinator_routes_presets.cpp` / `coordinator_routes_presets_impl.h` —
  the apply/merge logic is unchanged
- `token_ledger`, `agent_health` — no changes
- Python test suite — no scan anchors needed

## Acceptance Criteria
1. `GET /api/presets/:name/export` returns JSON with
   `Content-Disposition: attachment`.
2. `exportPreset("my-preset")` triggers a browser download.
3. `PresetImport` validates file JSON and saves via PUT; shows error when
   invalid.
4. `duplicatePreset("src", "src-copy")` creates a new preset from an existing one.
5. `./scripts/build_cpp_binaries.sh` — clean build.
6. 924 JS + 28 Python tests pass.
