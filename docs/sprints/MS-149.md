# MS-149 — Unified Architect + MLX History Path

**Epic:** MS-130 (post-ship polish)  
**Points:** 5  
**Branch:** `main`

## Problem

`mlx_session_store` tracked per-session message history but never injected it into requests to `mlx_lm.server`. Every call — whether from `/api/mlx/stream`, `/api/mlx/submit`, or `/api/architect/stream` — sent only a one-shot `[{system}, {user: prompt}]` messages array with no prior turns. Multi-turn continuity was silently broken for all MLX agents.

## What changed

### History injection (primary fix)

- **`agent_client_http.cpp`** — `call_agent_once` now accepts `session_id`. When provided and `engine == "mlx"`, it fetches history from `mlx_sessions().get_messages(session_id)` and injects it as the messages array (with system prepended). Falls back to one-shot if history is empty.
- **`agent_stream_llama.h`** — `stream_mlx` gets the same `session_id` param. Injects history the same way. After a successful response, appends the assistant turn back to `mlx_sessions()` so the next call sees it.
- **`agent_client.cpp`** — new `call_agent_in_session(agent, prompt, session_id)` public API. `call_agent_with_system` and `call_agent` remain unchanged.

### Unified dispatch (secondary fix)

Both MLX-direct and architect paths now write to and read from `mlx_session_store` for MLX agents:

- **`/api/mlx/submit`** — calls `call_agent_in_session` (was `call_agent`); history injected via `call_agent_once`.
- **`/api/mlx/stream`** — passes `session_id` to `agent_stream::stream_agent`; history injected in `stream_mlx`, assistant response written back.
- **`/api/architect/stream`** — seeds `mlx_sessions` with the user turn before dispatching to MLX agents, then passes `session_id` through all mode runners (`broadcast`, `pipeline`, `router` → `stream_parallel_agents` → `stream_agent`).

### Call chain change

```
Before: stream_agent(agent, sys, prompt, cb, cancel)
After:  stream_agent(agent, sys, prompt, cb, cancel, session_id="")
```

Default `""` preserves all existing callers (e.g. synthesis agent, classifier router) without change.

## Invariants

- User message is appended to `mlx_sessions` **before** the call so `get_messages()` inside `stream_mlx` / `call_agent_once` returns the full history including the current turn.
- Assistant response is written inside `stream_mlx` (streaming path); the submit route's existing explicit write handles the blocking path — no double-write.
- For architect sessions with multiple MLX agents in broadcast mode, each agent writes its own response — the session accumulates all assistant turns for that session key.
- Non-MLX agents (`engine == "llama"`, `"docker"`, `"vllm"`) are unaffected; `session_id` is accepted and silently ignored.
