# MS-75: RAG Re-Ranking + Relevance Score UI

## Goal
The current RAG pipeline retrieves the top-K chunks by cosine distance but
does no cross-encoder re-ranking — the chunks injected into the prompt may
not be the most relevant to the exact query. This sprint adds an optional
server-side re-ranking step using a simple keyword-overlap score (no extra
model required), exposes per-chunk relevance scores in the metadata, and
surfaces them in the `RagSources` UI.

## Background
`rag_client.h` returns `RagHit { text, source, chunk_idx, distance }`.
`coordinator_routes_dispatch_prepare.cpp` builds the `rag_block` string
from hits. The `meta.rag` field is passed to `RagSources.js` for display.
Currently `distance` (cosine) is the only signal; no query-overlap score is
computed.

## Scope

### C++ — re-ranking helper

- **`cpp_core/src/rag_rerank.h`** (new, inline) — `namespace rag_rerank`:
  ```cpp
  struct ScoredHit { RagHit hit; double relevance; };
  // Compute BM25-style term overlap score: count shared tokens between
  // query and chunk text, normalized by chunk length.
  double term_overlap(const std::string& query, const std::string& text);
  // Reorder hits by combined score: alpha * (1 - distance) + (1-alpha) * overlap.
  // alpha=0.6 by default (distance-weighted). Returns sorted descending.
  std::vector<ScoredHit> rerank(const std::string& query,
                                 const std::vector<RagHit>& hits,
                                 double alpha = 0.6);
  ```

- **`cpp_core/src/coordinator_routes_dispatch_prepare.h`** — add
  `bool rag_rerank = false;` to `DispatchRequest`.

- **`cpp_core/src/coordinator_routes_dispatch_prepare.cpp`** — read
  `rag_rerank` from request body; after retrieval, if `rag_rerank` is true,
  call `rag_rerank::rerank()` and rebuild `rag_block` from the re-ordered
  hits. Store per-hit relevance scores in `rag_meta` alongside existing fields.

### JS — re-ranking toggle + score display

- **`src/api/sseStreamReader.js`** / **`src/api/streamApi.stream.js`** —
  pass `rag_rerank: opts.ragRerank ?? false` in the request body.

- **`src/components/RagControlsPanel.js`** — add a "Re-rank" checkbox
  (disabled when `useRag` is false); sends `ragRerank` flag up via
  `onRagRerankChange` prop.

- **`src/components/RagHitRow.js`** — render relevance score badge
  (0.00–1.00, colour-coded green > 0.7, amber 0.4–0.7, grey < 0.4) when
  `hit.relevance` is present in `meta.rag`.

- **`src/components/RagSources.js`** — pass `relevance` field from hit
  metadata down to `RagHitRow`.
