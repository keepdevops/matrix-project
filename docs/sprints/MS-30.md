# MS-30 — BrewlateLayout Split + agent_client Refactor

**Sprint:** August 23 – September 5, 2026  
**Status:** In progress  
**Goal:** Eliminate the two largest LOC violations — `BrewlateLayout.js` (871 LOC, 3× the limit) and `agent_client.cpp` (298 LOC, approaching limit) — and land targeted follow-up from MS-29.

## Context

MS-29 cleared the C++ stream and proxy files. Two violations remain:

1. **`BrewlateLayout.js` is 871 LOC** — the dominant structural debt. It houses the entire Brewlatte UI: deploy state, configure panel, session tabs, agent grid, code results, RAG tab, mode selector, prompt input, monitor popout, and all event handlers. Splitting by feature panel is the right boundary.
2. **`agent_client.cpp` is 298 LOC** — 2 LOC under the limit, but growing with each sprint. Contains HTTP client calls, retry logic, and agent health probing that belong in separate files.
3. **`PromptInput.js` is 277 LOC** — the role-selector block added for Python modes (MS-25-3/MS-26-1) is the natural extraction target.
4. **`configApi.js` is 290 LOC** — orchestrate history functions and configure-status polling can be split into `orchestrateApi.js` (partially done) and `configureApi.js`.

## Item notes

### MS-30-1 — Split BrewlateLayout.js (871 LOC → 4–5 files ≤ 250 LOC each)

Natural boundaries (each becomes a sub-component):
- `BrewConfigPanel.js` — deploy state, profile selector, `useDeploy`, server layout preview (~200 LOC)
- `BrewSessionPanel.js` — conversation thread, final answer, RAG sources, metrics strip (~180 LOC)
- `BrewAgentsTab.js` — agent grid, flat-pick controls, stage outputs (~120 LOC)
- `BrewRagTab.js` — already exists as an inline function; promote to file (~100 LOC)
- `BrewlateLayout.js` — shell: tab state, popouts, header, wires sub-components (~200 LOC)

Critical: `useDeploy`, `applyProfile`, and `computeRiskEstimate` must stay co-located or be cleanly passed as props — avoid prop drilling depth > 2.

### MS-30-2 — Split agent_client.cpp

- Extract `probe_agent_health()` and related HTTP health-check logic to `agent_health_probe.cpp` (~60 LOC)
- `agent_client.cpp` stays with core HTTP streaming/retry (~240 LOC)

### MS-30-3 — Extract ModeParamControls.js from PromptInput.js

- The role-selector + depth/branching/prune_below block for Python modes (MS-25-3, MS-26-1) is ~60 LOC inside `PromptInput.js`
- Extract to `src/components/ModeParamControls.js`; import in `PromptInput.js`
- `PromptInput.js` drops from 277 → ~220 LOC

### MS-30-4 — Split configApi.js

- Move `fetchConfigureStatus`, `fetchLogs`, `fetchCacheStats`, `clearCache` to `configureApi.js`
- `configApi.js` keeps swarm-config read/write, agent prompt, health check
- Both files stay under 200 LOC; update `swarmApi.js` barrel re-export
