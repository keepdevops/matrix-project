# MS-28 — Test Coverage, CSS Polish, Timing Instrumentation

**Sprint:** July 26 – August 8, 2026  
**Status:** In progress  
**Goal:** Close the quality gaps exposed by MS-24–MS-27: zero Python test coverage for new orchestration modes and the history endpoint; missing CSS for `mode-option-description`; `total_ms = 0` in orchestrate metrics; and the HTTP 200 on stream validation errors.

## Context

MS-24–MS-27 shipped the full Python orchestration stack (4 modes, SSE streaming, RAG, history, metrics, UX). Post-ship review identified:

1. **No Python tests for any new Python mode** — `map_reduce`, `speculative`, `critic_debate`, `tree_of_thought` have 0 test coverage; `handle_orchestrate_stream`, `POST /api/history/entry`, `rag_xml` helper, and `_fetch_rag_chunks` are also untested
2. **CSS missing for `mode-option-description`** — class rendered by `ModeSelector` but not styled in `App.css`; description text is unstyled (inherits button font/size)
3. **Per-agent `total_ms = 0`** in orchestrate metrics — `MetricsStrip` shows correct token counts but 0s for timing; modes need per-agent wall-clock instrumentation
4. **SSE stream returns HTTP 200 on validation errors** — structural limitation (proxy commits to 200 before Python coord validates); needs a pre-flight check on the proxy side

## Item notes

### MS-28-1 — Python tests (highest priority)

Test targets with no coverage:
- `orchestration/modes/map_reduce.py` — `MapReduceMode.execute()`: chunks split, map phase, synthesizer, error path
- `orchestration/modes/speculative.py` — drafter/verifier loop, early termination
- `orchestration/modes/critic_debate.py` — generator/critic rounds, SHIP detection, max_rounds
- `orchestration/modes/tree_of_thought.py` — branching, scoring, prune_below, depth recursion
- `orchestration/modes/_helpers/__init__.py` — `rag_xml()` with empty/non-empty chunks
- `orchestration/mlx_coordinator/service_orchestrate.py` — `handle_orchestrate` (blocking), `handle_orchestrate_stream` (SSE), `_fetch_rag_chunks` (mocked), `POST /api/history/entry`
- Pattern: use `FakeBackend` from `tests/modes/test_registry.py`; mock `aiohttp.ClientSession` for RAG fetch

### MS-28-2 — CSS for `mode-option-description`

- Add `.mode-option-description` rule to `src/App.css` alongside `.mode-option-name` and `.mode-option-backend`
- Style: smaller font (0.7rem), muted color (`var(--color-muted)` or `opacity: 0.65`), no wrap, truncate at 1 line
- Ensure it looks right in all themes (light, dark, cvd-*) — use CSS variables, no hardcoded colors

### MS-28-3 — Per-agent timing in orchestrate stream

- In `handle_orchestrate_stream`: record `time.monotonic()` at each `agent_start` event per agent; compute elapsed at `agent_end` or next `agent_start` for the same agent
- Add `total_ms: int` to the `timings` dict alongside `completion_tokens`
- `tree_of_thought` note: generator and scorer run concurrently per depth; attribute elapsed to each individually

### MS-28-4 — Proxy pre-flight for `/api/orchestrate/stream`

- Current: proxy sends HTTP 200 + `Content-Type: text/event-stream` before Python coord validates; validation errors return HTTP 200 with error body
- Fix: proxy parses `mode` field from request body and sends HTTP 400 immediately if missing (already done for blocking endpoint — mirror that check before `set_chunked_content_provider`)
- For unknown mode: cannot validate without knowing the Python coord's mode registry; document as a known limitation
