# MS-90 — Automated Trajectory Quality Scoring for Distillation Export

**Linear title:** Trajectory quality scorer + distillation export enrichment
**Points:** 12
**Backlog item:** "Automated trajectory quality scoring for distillation export"

## Goal
Every `RlTrajectory` in the export bundle gets a computed `quality_score`
(0–1) that the distillation app can use to filter, weight, or stratify training
examples. The score combines TES, fidelity, annotation feedback, and
symbolic importance into a single signal — removing the need for the
distillation app to recompute these fields.

## Scope

### C++ — trajectory quality scorer

- **`cpp_core/src/trajectory_quality.h`** (new, inline) —
  ```cpp
  namespace trajectory_quality {

  struct QualityFactors {
      double tes;              // 0–1 from ms-87
      double fidelity_ratio;   // 0–1 from context gate
      double avg_importance;   // 0–1 from symbolic_importance
      double rag_hit_rate;     // 0–1
      int    annotation_rating; // 1=up, -1=down, 0=none
      bool   any_overrun;
  };

  // Weighted combination:
  //   tes * 0.35 + fidelity * 0.20 + importance * 0.20
  //   + rag * 0.10 + annotation_bonus * 0.15
  // annotation_bonus: +0.15 if rating=1, -0.20 if rating=-1, 0 if none
  // Clamped 0–1. Returns -1.0 if insufficient data.
  double compute(const QualityFactors& f);

  // Derive factors from a Trajectory JSON (rl_trajectory_logger format).
  QualityFactors from_json(const nlohmann::json& traj);
  }
  ```

- **`cpp_core/src/rl_trajectory_logger.h`** — add `double quality_score = -1.0`
  to `Trajectory`; compute and store it when `record()` is called.
  Include in `to_json()` output.

- **`cpp_core/src/coordinator_routes_annotations.h`** — when an annotation
  is saved (`POST /api/annotations`), look up the matching trajectory in
  `rl_traj::detail::buf()` by `run_id` and update its `annotation_rating`,
  `annotation_comment`, and recompute `quality_score`. This keeps the
  export bundle live without requiring a full rebuild.

### C++ — quality-filtered export

- **`cpp_core/src/coordinator_routes_rag_trajectory.h`** — extend
  `GET /api/export/rl-trajectories` to support `?min_quality=0.5` filter:
  only emit trajectories with `quality_score >= min_quality` (or quality_score
  == -1 which means unscored, include by default).

### JS — quality badge in history

- **`src/components/QualityScoreBadge.js`** (new) — small badge showing
  the quality score 0.00–1.00, colour-coded:
  green ≥ 0.7, amber ≥ 0.4, grey otherwise. Shown in `ConversationTurn`
  alongside TES and Fork buttons.

- **`src/components/ConversationTurn.js`** — add `QualityScoreBadge` when
  `entry._meta?.quality_score` is present (≥ 0).

- **`src/components/ExportFilterPanel.js`** — add `min_quality` slider
  (0–1, step 0.1) to the filter controls; include in export URL as
  `&min_quality=0.5`.

## Files NOT touched
- `symbolic_importance.h` — read-only dependency
- Python test suite — no scan anchors needed

## Acceptance Criteria
1. `trajectory_quality::compute()` returns higher scores for high-TES,
   annotated-up, low-overrun trajectories.
2. `quality_score` appears in every JSONL export line.
3. `?min_quality=0.7` filters export to only high-quality trajectories.
4. Saving a ▲ annotation updates the trajectory's quality score without restart.
5. `QualityScoreBadge` renders correctly in ConversationTurn.
6. `./scripts/build_cpp_binaries.sh` — clean.
7. 924 JS + 28 Python tests pass.
