# MS-25 — Python Mode Productization

**Sprint:** June 14 – June 27, 2026  
**Status:** **Complete** (merged to `main` via [#97](https://github.com/keepdevops/matrix-project/pull/97)–[#101](https://github.com/keepdevops/matrix-project/pull/101))  
**Goal:** Unlock the four Python orchestration modes (`map_reduce`, `speculative`, `critic_debate`, `tree_of_thought`) for UI selection via a C++ proxy bridge, with live memory cap enforcement tied to `GET /api/memory`.

## Context

MS-24 is fully shipped ([#93](https://github.com/keepdevops/matrix-project/pull/93)–[#95](https://github.com/keepdevops/matrix-project/pull/95) on `main`). Native C++ modes and live host RAM guardrails are live (`GET /api/memory`, `computeRiskEstimate` with `hostMemory`, SAFE auto-profile — MS-24-6 + MS-24-B).

Four Python modes exist under `orchestration/modes/` but are `enabled: false, ui: false` in `src/utils/modeManifestData.js`. MS-24-7 deferred them — no proxy ingress, invisible to UI. MS-25-1 is the unlock; all subsequent items depend on it.

## Item notes

### MS-25-1 — C++ proxy `/orchestrate` passthrough

- New `POST /orchestrate` route in `cpp_core/src/proxy_routes.cpp`
- Routes by `mode.backend === 'python'` in manifest; forwards to Python coordinator (`orchestration/manager.py`)
- C++ coordinator keeps native modes (`flat`, `pipeline`, `cascade`, `router`) unchanged
- llama/vLLM agents stay on C++ plane; only Python-mode requests forward

### MS-25-2 — `map_reduce` UI

- Flip `modeManifestData.js`: `map_reduce: { enabled: true, ui: true }`
- Expose `chunks` param (default 3) in PromptInput when mode is selected
- `orchestration/modes/map_reduce.py` (99 LOC) is already implemented
- Synthesizer output streams back via SSE through the passthrough

### MS-25-3 — `speculative` + `critic_debate` UI

- Same manifest flip pattern as MS-25-2
- Context budget guard: warn (not hard block) when `hostMemory.free_gb < memoryWeight × 4 GB`
- `orchestration/modes/speculative.py`, `critic_debate.py` already implemented

### MS-25-4 — Memory cap enforcement

- Extend `computeRiskEstimate` (`src/components/SwarmConfig.risk.js`) to factor `mode.memoryWeight` against live `free_gb`
- Hard block configure when `free_gb < mode.memoryWeight × threshold`
- Threshold sourced from `config.coordinator.profiles` (already wired — MS-24-B)
- Builds on `liveRamHigh` / `baseRamGb` from MS-24-B (#95)

### MS-25-5 — RAG-aware chunking for `map_reduce`

- Pass active RAG sources into chunk payloads before map stage
- Synthesizer cites retrieved chunks in final answer
- Leverages `orchestration/modes/_helpers/rag.py` + existing pgvector sidecar
