# MS-76: History Search + Response Cache Observability

## Goal
Two related observability gaps closed in one sprint:
1. The response cache (`response_cache.h`) tracks hits/misses/evictions but
   exposes none of it to Prometheus or the UI dashboard.
2. The history array (`CoordinatorState::history`) has no search endpoint —
   users can only page through it; there's no way to find a past conversation
   by keyword.

## Scope

### C++ — cache metrics in Prometheus

- **`cpp_core/src/coordinator_routes_metrics.h`** — extend `GET /api/metrics`
  with response cache counters:
  ```
  # HELP matrix_cache_hits_total Response cache hits since startup
  matrix_cache_hits_total 142
  # HELP matrix_cache_misses_total Response cache misses since startup
  matrix_cache_misses_total 58
  # HELP matrix_cache_size Current number of cached entries
  matrix_cache_size 37
  # HELP matrix_cache_evictions_total LRU evictions since startup
  matrix_cache_evictions_total 5
  ```
  Read from `response_cache::stats()`.

### C++ — history search endpoint

- **`cpp_core/src/coordinator_routes_history_search.h`** (new, inline) —
  `GET /api/history/search?q=<term>&limit=<n>` (default limit 20):
  Scan `st.history` (under `st.history_mutex`) for entries where
  `entry["prompt"]` or any agent-response value contains the query string
  (case-insensitive substring match). Return matching entries newest-first,
  capped at limit.

### JS — history search UI

- **`src/api/historyApi.js`** (new) — `searchHistory(query, limit)` →
  `GET /api/history/search?q=...&limit=...`.

- **`src/hooks/useHistorySearch.js`** (new) — debounced search hook (300ms);
  returns `{ results, loading, error }`. Clears results when query is empty.

- **`src/components/HistorySearch.js`** (new) — search input + results list.
  Each result shows: prompt (truncated 80 chars), timestamp, session badge.
  Clicking a result calls `onSelect(entry)` so the parent can load it into
  the conversation view.

### JS — cache stats panel

- **`src/hooks/useCacheStats.js`** (new) — polls `GET /api/cache` every 10s;
  returns `{ hits, misses, size, evictions, hit_rate }` where
  `hit_rate = hits / (hits + misses)` or 0.

- **`src/components/CacheStatsBar.js`** (new) — compact one-line display:
  `CACHE hit rate 71% · 37 entries · 5 evictions`. Hidden when cache is
  disabled (`size === 0 && hits === 0 && misses === 0`).

## Files NOT touched
- `response_cache.cpp` — no logic changes, only reading existing stats
- `coordinator_routes_cache.cpp` — no changes (existing PUT/GET/DELETE stay)
- Python test suite — no scan anchors needed

## Acceptance Criteria
1. `GET /api/metrics` includes `matrix_cache_hits_total` and siblings.
2. `GET /api/history/search?q=python` returns entries containing "python".
3. `HistorySearch` renders results and calls `onSelect` on click.
4. `CacheStatsBar` shows hit rate when cache is enabled.
5. `./scripts/build_cpp_binaries.sh` — clean build.
6. 924 JS + 28 Python tests pass.
