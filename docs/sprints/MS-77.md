# MS-77: Speculative Decoding Observability + Quality Pass Agent Selector

## Goal
Two UI/observability gaps in one sprint:
1. Speculative decoding (`draft_acceptance_rate`) is computed in
   `pressure_snapshot_llama.cpp` but never reaches the Prometheus endpoint
   or the JS pressure monitor.
2. The quality pass target agent is a string hard-coded in coordinator config
   (`coordinator.modes.<mode>.target_agent`). Users have no way to change it
   per-session without editing the config file.

## Background
`pressure_snapshot_llama.cpp` adds `draft_acceptance_rate` to the per-port
pressure JSON when `draft_max > 0`. This value flows into `meta.timings`
(via `agent_metrics`) — but no Prometheus metric and no UI gauge expose it.
The quality pass is triggered by `quality_pass: true` + `target_agent` in
the dispatch body; the frontend sends it from `useSubmitHandlers`.

## Scope

### C++ — speculative decoding Prometheus metric

- **`cpp_core/src/coordinator_routes_metrics.h`** — add
  `GET /api/metrics` entries for each agent that has `draft_max > 0`:
  ```
  # HELP matrix_agent_draft_acceptance Draft token acceptance rate (0–1)
  matrix_agent_draft_acceptance{agent="coder"} 0.72
  ```
  Read from `agent_metrics::snapshot()` — the snapshot JSON already contains
  `draft_acceptance_rate` per agent when available. Fall back to -1 when
  not present (no active speculative decode session).

- **`cpp_core/src/coordinator_routes_metrics.h`** — also expose
  `matrix_agent_kv_fill` per agent from the pressure snapshot already in
  `agent_metrics::snapshot()` (the field `kv_cache_usage_ratio`).

### JS — draft acceptance gauge

- **`src/components/PressureCluster.js`** — when a slot's pressure data
  includes `draft_acceptance_rate`, render a small acceptance bar:
  `DRAFT acc 72%` below the KV bar. Colour: green ≥ 0.7, amber ≥ 0.4,
  grey otherwise.

### JS — quality pass agent selector

- **`src/components/QualityPassSelector.js`** (new) — dropdown listing
  `activeAgents` names; label "Quality pass target". Default shows the
  coordinator-configured target. Emits `onTargetChange(name)`.

- **`src/hooks/useSubmitHandlers.js`** — accept `qualityPassTarget` param;
  include it as `context_policy.target_agent` in the dispatch body when
  `quality_pass: true` is set. This overrides the coordinator-side default
  for that single request.

- **`src/api/sseStreamReader.js`** / **`src/api/orchestrateApi.js`** —
  forward `qualityPassTarget` in the request body's `context_policy`.

## Files NOT touched
- `pressure_snapshot_llama.cpp` — draft acceptance rate already computed
- `modes/flat.cpp`, `modes/cascade_exec.h` — QP routing logic unchanged
- Python test suite — no scan anchors needed

## Acceptance Criteria
1. `GET /api/metrics` includes `matrix_agent_draft_acceptance` for agents
   with `draft_max > 0` (value `-1` when no recent data).
2. `PressureCluster` shows `DRAFT acc N%` when `draft_acceptance_rate` is
   present in slot pressure data.
3. `QualityPassSelector` renders a dropdown when `activeAgents.length > 0`.
4. Selecting a target and clicking Quality Pass sends `context_policy.target_agent`
   in the request body.
5. `./scripts/build_cpp_binaries.sh` — clean build.
6. 924 JS + 28 Python tests pass.
