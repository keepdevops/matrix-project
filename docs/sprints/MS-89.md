# MS-89 — Hardware Optimizations + Predictive UX + Export Polish

**Linear title:** KVFlow-style prefix caching, simulation, token visualization + distillation export UX
**Points:** 13
**Maps to:** Original MS-73 research plan (final sprint in the research sequence)

## Goal
1. Workflow-aware KV prefix caching — track shared prompt prefixes across
   agents and prioritize retaining them during eviction.
2. Hybrid routing that respects contract allocations when selecting agents.
3. Predictive simulation (dry-run) using contract + importance models to
   estimate token cost before dispatch.
4. `TokenFlowSankey` JS component visualizing token flow between agents.
5. Export UI polish: filters by session, date range, and format presets.

## Scope

### C++ — prefix cache tracker

- **`cpp_core/src/prefix_cache.h`** (new, inline) —
  ```cpp
  namespace prefix_cache {
  struct Entry {
      std::string prefix;   // first N chars of system+user prompt
      int         port;
      int         hit_count = 0;
      long long   last_seen_ms = 0;
  };
  // Record a prompt prefix for a port (called from agent_client_http.cpp).
  void record(int port, const std::string& prompt, int prefix_len = 512);
  // Returns ports sorted by hit count descending (most-shared first).
  std::vector<Entry> ranked();
  // Influence kv_importance: boost importance for high-hit-count ports.
  double prefix_importance_boost(int port);
  }
  ```
  Called from `agent_client_http.cpp` after each successful response.
  Used by `kv_importance_indexer` to boost score for cache-warm ports.

- **`cpp_core/src/kv_importance_indexer.h`** — `score_port()` accepts an
  optional `prefix_boost` parameter (default 0.0); adds it to the final score.

- **`cpp_core/src/coordinator_routes_dispatch.cpp`** — after importance
  scoring, call `prefix_cache::ranked()` and pass boosts to a second-pass
  importance recompute for the KV auto-clear decision.

### C++ — predictive simulation

- **`cpp_core/src/dispatch_simulation.h`** (new, inline) —
  `POST /api/simulate` (or called internally before dispatch):
  ```cpp
  struct SimResult {
      int    estimated_tokens;
      double estimated_tes;
      bool   would_overrun;
      int    effective_max_select;
      nlohmann::json agent_estimates; // { name: { allocated, expected_tokens } }
  };
  SimResult simulate(const DispatchRequest& dreq,
                     const BudgetHierarchy& budget,
                     const ContractLedger&  ledger,
                     const std::vector<Agent>& agents,
                     const std::string& mode_name);
  ```
  Uses contract allocations + agent `max_input_tokens` to estimate per-agent
  spend without running actual inference.

- **`cpp_core/src/coordinator_routes_simulate.h`** (new) —
  `POST /api/simulate` — accepts same body as `/api/architect`, returns
  `SimResult` JSON without dispatching. 20% accuracy target.

### JS — TokenFlowSankey

- **`src/components/TokenFlowSankey.js`** (new) — simple ASCII/SVG sankey
  showing token allocation flow: Budget → Mode → Agents.
  Uses `meta.contracts` and `meta.importance` from the last response.
  Renders as a column layout (no external library — pure CSS/React).

- **`src/components/ExportFilterPanel.js`** (new) — filter controls for
  `/api/export/rl-trajectories`:
  - Session ID input
  - Date range (from/to)
  - Format toggle: JSONL (default) or JSON array
  Calls `exportTrajectories()` with query params.

- **`src/api/trajectoryApi.js`** — extend `exportTrajectories()` to accept
  `{ sessionId, from, to, format }` filter options and append them as query
  params.

### JS — simulation UI

- **`src/hooks/useDispatchSimulation.js`** (new) — calls `POST /api/simulate`
  with the current prompt + active mode config; returns SimResult.

- **`src/components/SimulationPreview.js`** (new) — compact card showing
  estimated token cost, TES, max_select, and per-agent allocation before submit.
