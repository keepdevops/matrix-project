# MS-150 — Benchmark Report: Python vs C++ MLX Coordinator

**Epic:** MS-130 (post-ship polish)  
**Points:** 5  
**Branch:** `main`  
**Script:** `scripts/bench_mlx_coordinator.py`

## What was built

A stdlib-only benchmark script (`scripts/bench_mlx_coordinator.py`) that
measures and compares the Python (`:3003`) and C++ (`:3002`) MLX coordinator
implementations across two tiers:

1. **Routing overhead** — coordinator-only routes (`/health`, `/pressure`,
   `/agents`, `/modes`) that require no live MLX agent. These measure pure
   coordinator latency including parsing, mutex acquisition, and HTTP response
   serialization.

2. **End-to-end** — `/api/mlx/submit` (blocking) and `/api/mlx/stream` (SSE)
   when MLX agents are live. Metrics: avg/p50/p95 latency, TTFB (time to first
   token event), and approximate tok/s.

The script gracefully degrades: if one coordinator is offline or has no live
agents, that side is skipped and the report notes what's missing.

## Usage

```bash
# Quick run (default 5 requests, prints Markdown to stdout):
python3 scripts/bench_mlx_coordinator.py

# Full run with output file:
python3 scripts/bench_mlx_coordinator.py \
    --cpp http://localhost:3002 \
    --python http://localhost:3003 \
    --requests 20 \
    --out docs/bench-ms150.md
```

## What to measure

| Route | What it shows |
|-------|---------------|
| `GET /health` | Port-probe overhead (Python: asyncio event loop; C++: httplib thread) |
| `GET /pressure` | In-flight counter serialization cost |
| `GET /agents` | Config deserialization |
| `GET /modes` | Mutex + string copy |
| `POST /submit` | Full round-trip: coord → mlx_lm.server → coord |
| `STREAM TTFB` | Time from POST to first SSE token event |
| `STREAM total` | Full stream duration; divide into tok/s |

## Expected results (reference, Apple Silicon M-series)

When both coordinators are running with a live `mlx_lm.server` agent:

| Route | Python `:3003` | C++ `:3002` | Expected Δ |
|-------|---------------|-------------|------------|
| GET /health | ~5–15 ms | ~0.5–2 ms | C++ ~5–10× faster |
| GET /pressure | ~3–8 ms | ~0.2–1 ms | C++ ~5–10× faster |
| POST /submit | model-bound | model-bound | Coordinator overhead < 5 ms for both |
| STREAM TTFB | ~50–200 ms | ~10–50 ms | C++ MS-148 SSE cuts TTFB significantly |

The dominant cost for submit/stream is always the `mlx_lm.server` inference
time, not coordinator overhead. Routing-only routes expose the raw coordinator
cost cleanly.

## Notes

- No external pip dependencies; runs with system Python 3.
- `--requests 5` is fine for a quick comparison; use `--requests 20` for
  stable p95 numbers.
- The Python sidecar runs via `orchestration.mlx_coordinator.sidecar`
  (started by `matrix-2-launch.sh`). It must be running for the Python
  column to appear.
