# MS-29 — Refactor Overdue Files, DefaultLayout Parity, UI Tests

**Sprint:** August 9 – August 22, 2026  
**Status:** **Complete** (merged to `main` via [#120](https://github.com/keepdevops/matrix-project/pull/120)–[#123](https://github.com/keepdevops/matrix-project/pull/123))  
**Goal:** Reduce LOC debt in oversized C++ files, make DefaultLayout (Classic) fully functional with Python orchestrate modes, and expand UI test coverage to include orchestrate flows and new components.

## Context

MS-24–MS-28 added significant functionality without splitting files that grew past the 300 LOC limit. Three structural issues surfaced:

1. **`coordinator_routes_architect_stream.cpp` is 359 LOC** — over limit; contains both SSE dispatch logic and synthesis routing that belong in separate files
2. **`proxy_routes.cpp` is 280 LOC** — approaching limit; orchestrate routes (`/api/orchestrate`, `/api/orchestrate/stream`) can be extracted to `proxy_routes_orchestrate.cpp`
3. **DefaultLayout (`DefaultLayout.js`) has no orchestrate awareness** — Classic layout users who select a Python mode see a broken experience: no Final Answer panel for orchestrate results, no mode descriptions in selector, no citation panel
4. **UI tests cover only `test_buttons.py`** — no coverage for ModeSelector descriptions, orchestrate history entries in ConversationThread, citation panel, or orchestrate progress indicator

## Item notes

### MS-29-1 — Split coordinator_routes_architect_stream.cpp (359 LOC → 2 files)

- Extract synthesis routing logic into `coordinator_routes_architect_synthesis.cpp`
- Keep SSE dispatch and event streaming in `coordinator_routes_architect_stream.cpp` (target: ≤ 250 LOC each)
- Update `coordinator.cpp` registration call; no behaviour change

### MS-29-2 — Extract proxy orchestrate routes (proxy_routes.cpp 280 → ~220 + ~80)

- Move `POST /api/orchestrate` and `POST /api/orchestrate/stream` handlers to new `proxy_routes_orchestrate.cpp`
- New header `proxy_routes_orchestrate.h` with `register_proxy_orchestrate_routes(svr)`
- Call from `register_proxy_routes()` in `proxy_routes.cpp`
- Add to `build_cpp_binaries.sh` compilation list

### MS-29-3 — DefaultLayout orchestrate parity

- When `activeMode` is a Python orchestrate mode and `finalAnswer` is set, show `FinalAnswerPanel` in DefaultLayout (currently only shown in BrewlateLayout's session tab)
- ConversationThread: badge history entries with `_orchestrate: true` flag as "🐍 mode_name" so users can distinguish them from streaming runs
- Pass `activeMode` to `ModeSelector` in DefaultLayout so descriptions render (already works in Brewlatte — just needs wiring in Classic)

### MS-29-4 — UI tests for new components

- `tests/ui/test_orchestrate_ux.py` (new): ModeSelector descriptions visible, orchestrate history entry renders with `_orchestrate` badge, citation panel appears when `lastMeta.rag` is set
- `tests/ui/test_mode_selector.py` (new): all 8 modes visible, description subtitle rendered, backend badge on Python modes
- Extend `test_buttons.py`: orchestrate progress indicator (`brew-brewcast-phase`) renders during loading
