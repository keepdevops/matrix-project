# MS-151 — CMake MLX Embed (Darwin arm64)

**Epic:** MS-130 research track  
**Points:** 5  
**Branch:** `main`  
**Gate:** gates MS-152 (in-process 4B generate spike)

## What was built

CMake build infrastructure and a thin `mlx_embed` wrapper that proves the
C++ → Metal path compiles, links against `libmlx.dylib`, and dispatches work
to the GPU.

### Files

| File | Purpose |
|------|---------|
| `cpp_core/CMakeLists.txt` | CMake project for the embed spike (Darwin arm64 only) |
| `cpp_core/src/mlx_embed.h` | Public API: `is_metal_available()`, `device_name()`, `probe_matmul(n)` |
| `cpp_core/src/mlx_embed.cpp` | Implementation using `mlx::core` C++ API |
| `tests/cpp/mlx_embed_probe.cpp` | Standalone probe binary; prints Metal availability + GFLOPS |
| `scripts/build_mlx_embed.sh` | Build + run script; auto-discovers MLX prefix |

### API surface (`mlx_embed` namespace)

```cpp
bool        is_metal_available();       // mlx::core::metal::is_available()
std::string device_name();             // mlx::core::device_info() → device_name
ProbeResult probe_matmul(int n=512);   // n×n float32 matmul, timed after warm-up
```

`ProbeResult` carries `ok`, `elapsed_ms`, `gflops`, and `error`.

## Build

```bash
# Requires: MLX installed in conda mlx-env (or set MLX_PREFIX)
bash scripts/build_mlx_embed.sh              # default n=512
bash scripts/build_mlx_embed.sh --n 1024     # larger matmul
bash scripts/build_mlx_embed.sh --clean      # clean rebuild

# Or directly:
MLX_PREFIX=~/miniforge3/envs/mlx-env \
  cmake -S cpp_core -B build/mlx_embed \
        -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build build/mlx_embed --target mlx_embed_probe
./build/mlx_embed/mlx_embed_probe 512
```

**Note:** If `CFLAGS`/`LDFLAGS` are set to WASI SDK paths (common in some
developer environments), the build script unsets them automatically before
invoking CMake to prevent the compiler probe from targeting wasm32.

## Results (Apple M3 Max)

```
Metal available : yes
Device          : Apple M3 Max
512×512 float32 matmul  → 0.77 ms   /  350 GFLOPS
1024×1024 float32 matmul → 1.78 ms  / 1206 GFLOPS
```

## Go/no-go note for MS-154

MS-154 gate criterion: ≥30% tok/s improvement OR TTFB reduction vs HTTP path.
The 1.2 TFLOPS demonstrated here is ~10× the FP32 compute needed for 4B model
inference (typical ~100–150 GFLOPS for forward pass), which is a necessary but
not sufficient condition. The actual benchmark happens in MS-152 / MS-153.

## MLX version

MLX 0.31.1 (`~/miniforge3/envs/mlx-env`).  Key deps for `libmlx.dylib`:
`Metal.framework`, `Accelerate.framework`.
