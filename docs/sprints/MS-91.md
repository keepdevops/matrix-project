# MS-91 — Advanced Entropy-Guided KV Policies + Multi-Swarm Contract Negotiation

**Linear title:** Entropy-guided layer-wise KV eviction + multi-swarm resource negotiation
**Points:** 15
**Backlog items:**
- "Advanced entropy-guided layer-wise KV policies"
- "Multi-swarm resource negotiation via contracts"

## Goal
1. Upgrade `kv_importance_indexer` with a layer-aware entropy proxy —
   simulate which "layers" of the KV context (recent vs. early vs. middle)
   have highest entropy, and prefer evicting low-entropy early layers first.
2. Add multi-swarm contract negotiation: when multiple coordinator instances
   share resources (via a shared config service), agents can negotiate
   allocation limits across swarms rather than each swarm operating in isolation.

## Scope

### C++ — layer-aware KV entropy

- **`cpp_core/src/kv_layer_entropy.h`** (new, inline) —
  ```cpp
  namespace kv_layer {
  struct LayerProfile {
      int    port;
      double early_entropy;   // entropy of first 25% of context
      double middle_entropy;  // entropy of middle 50%
      double recent_entropy;  // entropy of last 25%
      double eviction_priority; // 0=keep, 1=evict (computed from above)
  };
  // Segment a text into layers and score entropy per segment.
  LayerProfile profile(int port, const std::string& full_context);
  // Given a list of port contexts, rank by eviction priority (highest first).
  std::vector<LayerProfile> rank_for_eviction(
      const std::map<int, std::string>& port_contexts);
  }
  ```
  Entropy per segment = `symbolic_importance::entropy_score(segment)`.
  `eviction_priority = 1.0 - early_entropy * 0.6 - middle_entropy * 0.3
                       - recent_entropy * 0.1`
  (recent context always has lowest eviction priority — preserve it).

- **`cpp_core/src/kv_importance_indexer.h`** — `score_port()` gains an
  optional `LayerProfile*` parameter; when provided, blends
  `layer_score = 1.0 - profile->eviction_priority` into the final score
  with weight 0.3.

- **`cpp_core/src/coordinator_routes_dispatch.cpp`** — after auto-clear
  decision, if KV pressure > 0.85, compute `kv_layer::rank_for_eviction()`
  from last-known agent outputs and pass to `kv_auto_clear::clear_kv()`.

### C++ — multi-swarm contract negotiation

- **`cpp_core/src/swarm_negotiator.h`** (new, inline) —
  ```cpp
  namespace swarm_negotiator {
  struct NegotiationRequest {
      std::string swarm_id;
      std::string agent_name;
      int         requested_tokens;
      int         priority;          // 1=low, 5=high
  };
  struct NegotiationResult {
      int  granted_tokens;
      bool approved;
      std::string reason;
  };
  // POST to config service /api/negotiate (if MATRIX_SWARM_CONFIG_SERVICE set).
  // Falls back to local budget if config service unavailable.
  NegotiationResult negotiate(const NegotiationRequest& req,
                               const std::string& config_service_url);
  }
  ```
  Called from `coordinator_routes_dispatch.cpp` before contract init when
  `MATRIX_SWARM_CONFIG_SERVICE` env var is set. Allows the config service
  to arbitrate across multiple coordinator instances.

- **`cpp_core/src/coordinator_routes_dispatch.cpp`** — when negotiation is
  enabled and returns a `granted_tokens` value, use it to override the
  hierarchy-resolved budget for that agent.

- **`cpp_core/src/coordinator_routes_negotiate.h`** (new) —
  `POST /api/negotiate` — the coordinator can also *act as* the negotiation
  server for a multi-swarm setup:
  ```json
  { "swarm_id": "...", "agent_name": "coder", "requested": 2000, "priority": 3 }
  → { "granted": 1500, "approved": true, "reason": "capped at 75% of global" }
  ```
  Simple rule: grant `min(requested, global_budget * 0.75 / active_swarms)`.
  Tracks active swarm IDs in `CoordinatorState`.
