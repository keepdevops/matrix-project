# MS-27 — Orchestrate Polish: RAG, History, Metrics, UX

**Sprint:** July 12 – July 25, 2026  
**Status:** In progress  
**Goal:** Close the remaining gaps in the Python orchestration stack — `tree_of_thought` RAG injection, session history persistence for orchestrate runs, telemetry, and Brewlatte UX polish for multi-depth modes.

## Context

MS-24–MS-26 shipped all four Python modes with SSE streaming, memory caps, and RAG context. Three gaps remain after the MS-26 smoke:

1. **`tree_of_thought` has no RAG injection** — `speculative` and `critic_debate` got it in MS-26-3 via `rag_xml()` in `_helpers/__init__.py`, but `tree_of_thought` was not updated (different prompt structure, branch-per-depth)
2. **Orchestrate runs don't persist to session history** — `loadHistory()` is called after orchestrate completes but the coordinator's history store only tracks streaming (`/api/architect/stream`) runs, not `/api/orchestrate` runs
3. **No per-run metrics for orchestrate** — `MetricsStrip` shows timing for streaming runs but orchestrate `lastMeta` has only `wall_ms`; no per-agent token counts or depth/round breakdowns
4. **UX gaps found in smoke** — mode selector has no descriptions; `tree_of_thought` with depth 2 + branching 3 produces 9 agent calls with no progress indication beyond token streaming; SSE stream returns HTTP 200 on validation errors (structural limitation noted)

## Item notes

### MS-27-1 — `tree_of_thought` RAG injection

- Import `rag_xml` from `._helpers` (already shared across map_reduce, speculative, critic_debate)
- Inject `rag_block` into `gen_branch` prompt (between system and query+prior) and `score` prompt
- Gate on `ctx.params.get("rag_context")` — same pattern as other modes
- `service_orchestrate.py` already covers `tree_of_thought` in the `use_rag` gate (broadened in MS-26-3)

### MS-27-2 — Orchestrate session history persistence

- Add `POST /api/sessions` (or extend existing history endpoint) on the C++ coordinator to accept and store an orchestrate result `{prompt, result, mode, session_id, wall_ms}`
- `useSwarm.js` orchestrate `onDone` calls the history store after setting `finalAnswer`
- `loadHistory()` then picks it up — orchestrate runs appear in the conversation thread alongside streaming runs
- Minimal schema: same `{_prompt, _final, _meta, session_id}` shape the UI already reads

### MS-27-3 — Per-run orchestrate metrics

- Extend `done` event meta with per-agent token counts (count tokens from SSE stream in `handle_orchestrate_stream`, accumulate per `agent_id`)
- Add `timings` key to orchestrate `lastMeta` (keyed by agent_id, value = ms elapsed) so `MetricsStrip` renders it without changes
- For `tree_of_thought`: include `depth_reached`, `branches_pruned`, `top_score` from existing mode result meta

### MS-27-4 — Mode selector descriptions + orchestrate progress UX

- Add `description` field to `modeManifestData.js` entries; render as tooltip or subtitle in mode selector (both Brewlatte and Classic)
- `tree_of_thought` progress: show depth counter in agent card header during streaming (e.g. "depth 1/2, branch 3/3") using `agent_start` event `meta.depth`
- `critic_debate`: show round counter from `meta.round` in agent card header
