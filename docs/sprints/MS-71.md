# MS-71: Per-Agent Token Cap Enforcement + Budget Reset UI

## Goal
Harden per-agent token caps (already stored in `agent.max_input_tokens`)
by enforcing them on the completion side as well, add a `max_output_tokens`
field so both sides of the agent call are bounded, and expose a budget-reset
button in the UI so users can clear the session ledger without reconnecting.

## Scope

### C++ — output cap enforcement

- **`cpp_core/src/agent.h`** — add `int max_output_tokens = 0;`

- **`cpp_core/src/coordinator_setup_wire.h`** — read `max_output_tokens`
  from agent config alongside existing `max_tokens` read.

- **`cpp_core/src/agent_client_http.cpp`** — when `agent.max_output_tokens > 0`,
  add `"num_predict": agent.max_output_tokens` to the llama/mlx request body
  (already constructing the JSON body before POST). This caps generation length
  server-side rather than truncating post-hoc.

- **`cpp_core/src/coordinator_routes_token_budget.h`** — add
  `DELETE /api/token-budget/:session_id` route that calls
  `token_ledger::reset(session_id)` and returns `{"reset": true}`.

### JS — budget reset

- **`src/api/tokenBudgetApi.js`** — add `resetTokenBudget(sessionId)` →
  `DELETE /api/token-budget/:session_id`.

- **`src/hooks/useTokenBudget.js`** — expose `reset()` action that calls
  `resetTokenBudget` and immediately clears local state to zero.

- **`src/components/TokenBudgetBar.js`** — add a small "↺ reset" button
  next to the progress bar; disabled when `budget === 0` (unlimited).
  Calls `onReset` prop, shows brief "Reset" success flash.

- **`src/components/TokenBudgetGrid.js`** — add `max_output_tokens` column
  (editable int, saves via existing agent tokens PUT route); place after
  the existing `max_input_tokens` column.

### JS — agent config validation
- **`src/utils/agentConfigSchema.js`** (new or extend existing) — add
  `max_output_tokens: z.number().int().min(0).optional()` to the agent Zod
  schema so the config panel validates both cap fields before saving.

## Files NOT touched
- `synthesis_budget.cpp` — no change
- `modes/router.cpp` — no foreman changes
- Python test suite — no scan anchors needed

## Acceptance Criteria
1. Setting `"max_output_tokens": 512` in an agent config results in
   `num_predict: 512` in the llama POST body (verify via coordinator stdout log).
2. `DELETE /api/token-budget/:session_id` returns `{"reset": true}` and clears
   the ledger entry (`GET` afterwards shows `consumed: 0`).
3. TokenBudgetBar "↺ reset" button clears the bar immediately in the UI.
4. TokenBudgetGrid shows both `max_input_tokens` and `max_output_tokens` columns.
5. `./scripts/build_cpp_binaries.sh` — clean build.
6. 924 JS + 28 Python tests pass.
