# MS-69 Sprint — Context Management + Smart CLEAR KV

**Branch:** `cursor/ms-69-sprint`

## Goal
Prevent context window overflows before dispatch and automatically clear
KV cache when the swarm is idle and pressure diverges from the current
query. Two independent features that share the "context headroom" theme.

---

## 1. Summarization Gate

### Trigger
Before each non-followup dispatch, compare `len(effective_prompt)` against
a configurable `max_input_chars` threshold. If exceeded, route the prompt
through a designated **context agent** (tagged `"context"`) that summarises
it before the main dispatch continues.

### Schema addition (`coordinator.json`)
```jsonc
{
  "coordinator": {
    "context_gate": {
      "enabled": true,
      "max_input_chars": 8000,      // trigger threshold
      "context_agent": "foreman"    // agent to call for summarisation
    }
  }
}
```

### New C++ files

**`cpp_core/src/context_gate.h`** — inline helpers, included by `coordinator_routes_dispatch.cpp`:

```cpp
namespace context_gate {

struct Config {
    bool        enabled         = false;
    int         max_input_chars = 8000;
    std::string context_agent;
};

Config load(const nlohmann::json& coordinator_block);

// Returns summarised prompt, or original if gate not triggered / no agent.
std::string maybe_summarise(const Config& cfg,
                            const std::vector<Agent>& agents,
                            const std::string& prompt);
} // namespace context_gate
```

`maybe_summarise` calls `call_agent_with_system()` with the context agent
and a fixed summarisation system prompt:

> "You are a context compressor. Summarise the following input concisely,
> preserving all key facts, code snippets, and requirements. Output only
> the summary — no preamble."

### Modified C++ files

**`cpp_core/src/coordinator_context.h`**:
Add `context_gate::Config context_gate_config;` to `CoordinatorState`.

**`cpp_core/src/coordinator_setup.cpp`**:
Load `context_gate_config` from `config["coordinator"]["context_gate"]`
after `apply_coordinator_section`.

**`cpp_core/src/coordinator_routes_dispatch.cpp`**:
After RAG + followup expansion, before ModeContext construction:
```cpp
dreq.effective_prompt = context_gate::maybe_summarise(
    st.context_gate_config, mode_agents, dreq.effective_prompt);
```
Also stamp `meta.context_gate = {triggered: bool, original_chars: N, summary_chars: M}`
when gate fires.

### JS

field surfaces in `lastMeta` → MetricsStrip can display it as a badge.

## 2. Auto CLEAR KV

### Logic
After each successful dispatch, if KV pressure exceeds a threshold AND the
new query's embedding diverges significantly from the previous session query,
automatically issue a cache clear to the proxy.

### Divergence metric
Reuse the existing `rag_embed` C++ infrastructure (`rag_embed.h`, `blake2b.h`).
Compute `cosine_distance(embed(prev_query), embed(curr_query))`.
Threshold: `distance > 0.6` (embeddings are far apart → topic switch).

Combined trigger: `kv_pressure > 0.75 AND cosine_distance > 0.6 AND no agents running`.

### New C++ files

**`cpp_core/src/kv_auto_clear.h`** — inline helpers:

```cpp
namespace kv_auto_clear {

struct State {
    std::vector<float> last_embedding;
    double             last_pressure = 0.0;
};

// Returns true if auto-clear should fire.
bool should_clear(State& st,
                  const std::string& query,
                  double kv_pressure,
                  double divergence_threshold = 0.6,
                  double pressure_threshold   = 0.75);

// Call proxy DELETE /api/cache endpoint.
void clear_proxy_cache(const std::string& proxy_url);

} // namespace kv_auto_clear
```

`should_clear()`:
1. Embeds `query` using `rag_embed::embed_query()` (already exists in `rag_embed.h`)
2. Computes cosine distance vs `st.last_embedding`
3. Checks `kv_pressure > pressure_threshold && distance > divergence_threshold`
4. Updates `st.last_embedding` and returns decision

**`cpp_core/src/coordinator_context.h`**:
Add `kv_auto_clear::State kv_auto_clear_state; std::mutex kv_auto_clear_mutex;`

**`cpp_core/src/coordinator_setup.cpp`**:
Read `coordinator.auto_clear_kv.proxy_url` (defaults to `http://127.0.0.1:3001`).

**`cpp_core/src/coordinator_routes_dispatch.cpp`**:
After successful `dispatch_write_history`, check auto-clear:
```cpp
if (dreq.kv_pressure > 0.0) {
    std::lock_guard<std::mutex> lk(st.kv_auto_clear_mutex);
    if (kv_auto_clear::should_clear(st.kv_auto_clear_state,
                                    dreq.prompt, dreq.kv_pressure)) {
        kv_auto_clear::clear_proxy_cache(st.proxy_url);
        envelope["meta"]["auto_clear_kv"] = true;
    }
}
```
