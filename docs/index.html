What it is

Matrix Swarm is a local-first orchestration layer for open-weight LLMs. Spin up a fleet of role-specialized agents — Architect, Programmer, Security, DevOps, and more — then broadcast one prompt to all of them, pipe it through a sequence, or let a Router model dispatch each task to the best fit.

Models run entirely on your hardware: MLX + llama.cpp on Apple Silicon, vLLM on Linux/CUDA. Nothing leaves the box. Built for engineers who want Cursor-class productivity without sending their codebase to the cloud.

Features & requirements

Key Features

  • 16+ specialized agents (Architect, Programmer, DevOps, Security, etc.)
  • Run MLX + llama.cpp concurrently on Apple Silicon, or vLLM on Linux/CUDA (via Docker Model Runner) — mix backends per agent
  • Four coordinator modes: Flat (broadcast), Pipeline (sequential), Cascade (mixture-of-agents), Router (smart dispatch)
  • Real-time code extraction & editing, named mode presets, live system-prompt editing
  • Per-agent circuit breaker, retry-with-backoff, pipeline skip-with-warning
  • Streaming SSE dispatch + per-run metrics dashboard (ms / tokens per agent)

Requirements

  • macOS (Apple Silicon) — MLX + llama.cpp
  • Linux (NVIDIA GPU, CUDA 12+) — vLLM via Docker Model Runner
  • Node.js ≥ 18
  • Local GGUF / MLX / HF models
  • 16GB+ RAM (32GB+ recommended)

Resilience

  • Circuit breaker — 3 failures in 60 s trip; 30 s cooldown then half-open re-probe. Surfaces in meta.excluded_unhealthy and a red banner in PER-MODE ROSTER.
  • Retry-with-backoff — one retry (250 ms) on 5xx / empty body / timeouts. 4xx never retries.
  • Skip-with-warning — failed pipeline stage logged in meta.errors[]; downstream gets the previous good output.
  • Synthesis safety — cascade synthesizer never sees error markers from failed parallel agents.

Streaming SSE — POST /api/architect/stream

  • flat: token* · agent_done* · metrics · done
  • cascade: + synthesis_start before reducer
  • pipeline: stage per step, optional synthesis_start
  • router: selected first, then tokens from chosen agents

Per-run metrics

  • meta.wall_ms + meta.timings { agent: { calls, total_ms, completion_tokens } } on every envelope.
  • RUN METRICS strip below FINAL ANSWER renders per-agent bars ranked by ms, with token counts and % of total agent time.
  • Cache hits show 0 ms (short-circuit). Streaming token counts are word-counts (~25–40% off a true tokenizer).

Persistence & presets

  • Active config (--config) — what the coordinator reads on startup.
  • Source config (MATRIX_SOURCE_CONFIG) — user-editable; survives UI redeploy.
  • Presets — named bundles of (mode, agents, synthesizer, max_select). CRUD + apply via /api/presets.
  • Live prompt edits — PUT /api/agents/<name>/prompt mirrors to both files and clears the response cache.

FAQ

Do I need a GPU?

No. On Apple Silicon, MLX and llama.cpp use the unified memory and Neural Engine. On Linux, vLLM needs an NVIDIA GPU (CUDA 12+). CPU-only llama.cpp also works — just slower.

Where do models come from?

You bring your own GGUF (llama.cpp), MLX, or HuggingFace weights. Matrix Swarm doesn't ship models. Recommended starters: Llama 3, Qwen 2.5, DeepSeek-Coder.

What's the difference between Flat, Pipeline, Cascade, and Router?

Flat broadcasts your prompt to all agents in parallel. Pipeline chains them in a fixed sequence (e.g., Architect → Programmer → Reviewer), with an optional synthesizer that consolidates stage outputs. Cascade is mixture-of-agents: parallel broadcast plus a synthesizer that reduces every response into one consolidated answer. Router uses a classifier (foreman by default) to pick up to max_select agents from the roster, hinted by live KV-cache pressure.

Can I save and reuse mode configurations?

Yes — Mode presets bundle (mode, agents, synthesizer, max_select) under a name like design-review or router-fast. One click switches modes and applies the bundle. Presets persist across coordinator restarts and (with MATRIX_SOURCE_CONFIG set) UI redeploys.

What happens when an agent fails?

A per-agent circuit breaker trips after 3 failures in 60 s and excludes that agent from dispatch for 30 s, then half-opens to re-probe. Transient HTTP failures retry once with 250 ms backoff. In pipeline mode, a failed stage is recorded in meta.errors[] and the next stage receives the previous good output instead of an error message. Cascade filters failed agents out of the synthesizer's input.

Can I see how long each agent took?

Every dispatch envelope carries meta.timings (calls, total_ms, completion_tokens per agent) and meta.wall_ms. The RUN METRICS strip below FINAL ANSWER renders this as a per-agent bar chart. Streaming SSE emits the same payload as a final metrics event before done.

Can I edit an agent's system prompt at runtime?

Yes. Click the pencil (✏️) next to any agent in CONFIGURE. PUT /api/agents/<name>/prompt updates the prompt in memory, rewrites both the active and source config files, and clears the response cache. Tuning foreman's prompt is the single biggest lever on router quality.

Is anything sent to the cloud?

No. Inference, code extraction, and config all happen locally. There are no telemetry calls. (You can optionally point an agent at a remote OpenAI-compatible endpoint if you want — but it's off by default.)

How do I add a custom agent?

Drop a JSON entry into your swarm-config.json with a system prompt, model binding, and role. See swarm-config-16gb.json in the repo for examples.

Is there a Docker install?

The CLI installs via npm. Docker is used to run vLLM model servers (via Docker Model Runner on ports 8080–8083) when running the Linux/CUDA backend. See docker/Dockerfile.vllm-metal.
